# 実装の今の姿

コードの構成、仕様書が実装者に任せた部分の決定、確認のしかたを書きます。ルールと数値は `docs/spec.md` が正で、ここには写しません。コードを変えたら、同じ変更の中でこの文書の該当する節を書き換えます。

依存の向きは `app` → `render`・`audio`・`bots` → `core` の一方向です。`core` はほかのどこも読みません。

## core の作り

- 状態は関数を持たないただのデータで、`JSON.stringify` でそのまま比べられる。再現性のテストはこれを使っている。
- 敵の列はただの配列で、古い順（手前から奥）に並ぶ。列の途中の敵も倒れるので、倒した敵はその場で配列から抜く。
- 埋まり度は合計を数え直さず、敵の増減のたびに足し引きする。
- 乱数は、ブロック用（`state.deck.rng`）、敵の出現用（`state.spawnRng`）、敵の位置用（`state.positionRng`）を状態に持つ。ボット用は `src/bots/bot.ts` が、見た目用は `View` が持つ。
- 弾が当たる相手は「敵の列を先頭から見て、プレイヤーの列に重なる最初の敵」。奥行きの値はロジックに持たず、並び順だけで手前・奥が決まる。
- 弱点の位置と会心の判定は `state.ts` の `weakPointOf`・`isCritical` にあり、`step`・ボット・描画が同じ関数を使う（描画が別の式で判定すると、金色の表示と実際のダメージがずれるため）。
- 数式の計算の順序と、乱数を引く順番は参照シミュレータに合わせてある。種 0〜9 の生存時間が全ボットで参照と小数第 2 位まで一致する。

## 画面の作り

- 本編もデモも `Session` が同じ `step` を回す。違いは、立ちたい横位置を人の入力から取るか、デモ AI から取るかと、効果音の出口を渡すかどうかだけ。デモの字幕のきっかけのうち、出来事にないもの（あと少しで見捨てた、空振りし始めた）は、デモ AI の `rule`・`missing` の変わり目を `Session.advance` が拾って返す。
- 後ろでデモが流れている画面（タイトルと、タイトルから開いたショップ）かどうかは `App.onTitle` で見る。表示類（`drawHud` の `demo`）とキャンバスの置き方（`inGameLayout`）は、これで切り替える。
- `View` は core の状態を読むだけで書き換えない。敵の見た目（奥行き、絵の変種）は、敵の通し番号をキーにした表で持つ。横位置はロジックの値を使う。
- `View.updateAim` が、弾の列が今どこに当たっているか、会心かどうか、弱点が画面のどこにあるかを毎フレーム求める。当たり方は `step` の手順 8 と同じ式で、弾・数字・狙いの表示・的の印・撃たれた敵の点滅はすべてこの結果を使う。
- 敵は列の後ろほど奥にいるので、列を後ろから描けば奥から手前の順になる（並べ替えをしない）。
- 画面の縁を赤くする枠は、起動時に 1 枚の絵にしておき、濃さだけを変えて重ねる。
- 演出と音は、`step` が返した出来事を `View.handle` が受けて出す。射撃と命中は出来事ではなく、`View.update` が発射数から弾と数字を作る。
- レーザーと波動砲は弾ではなく、プレイヤーから標的までの光の帯として描く。ねこは弾も帯も出さず、標的の位置に数字ときらめきだけを出す。
- 開発サーバーで動かしているときだけ、`window.app` からアプリの状態に触れる（本番ビルドには含まれない）。

## 実装で決めたこと

仕様書が実装者に任せた、見た目・音・文言の決定です。

### 見た目

- 絵柄の決まりは仕様書 6.9 節。背景は起動時に絵にしておく。遠景（空、街並み、海）は時間帯ごとに 4 枚を等倍で、橋と手前の足場は 1 枚を 2 倍の解像度で持ち、遠景 2 枚を混ぜた上に橋を重ねる。雲、海のきらめき、帯を流れる矢羽根だけを毎フレーム描く。
- スプライトは `make()` が、絵の形をそのまま濃紺で塗った版を 12 方向にずらして重ね、輪郭にする。撃たれたときに重ねる白い版（ID の末尾に `#flash`）も同じ仕組みで作る。
- プレイヤーは奥を向いた後ろ姿で、武器は体の右に構える（頭に帽子を積むため）。ロジックの横位置は武器（弾の列）の位置で、体はその左に描く。相棒は防衛線の上に左・右・中央の順で並び、敵の先頭へ緑の線を出す。火薬で撃つ武器（エアガン〜バズーカ）は銃口が光る。
- 未読通知は、アプリ 3 種類 × バッジの数字 2 通りの、6 通りの絵を使い回す。敵の名前、初登場のときのひとこと（`intro`）、倒したときのひとこと（`defeat`）は `src/core/balance.ts` の `ENEMIES` に、ボスの台詞（`BOSS_LINES`）、ラッシュのひとこと（`RUSH_LINES`）も同じファイルにある。5 体目以降のボス（「真・」）は紫の光をまとう。
- 敵は現れた瞬間に小さく、すぐ元の大きさへふくらむ。歩いている間は小さく跳ねる。ブロックは、撃たれている間と残り 15% 未満のときに震える。
- ダメージの数字は、標的の絵や文字に重ならないよう標的の少し上に出し、少し傾ける。会心の数字は金色（白から黄のグラデーション）で、文字を 22 から 30 に大きくする。
- 弱点の的の印は、濃紺の輪郭の上に白（会心中は金色）の輪と十字。会心中は後ろに金色の光を重ねて細かく脈打たせる（画面全体は光らせない）。大きさは奥行きに合わせて縮める。
- 会心の説明（「会心！ 真ん中に当てるとダメージ 2 倍」）は、本編で、その回で初めて会心が出たときに 1 回だけ出す。デモでは出さない（タイトルの文字と重なるため。`View.tips`）。
- WAVE 番号は、ウェーブが変わった直後に一瞬大きくなる。リザルトのスコアは 0.8 秒かけて数え上がる。
- タイトル画面では、ロゴの後ろで光の筋が回り、「今すぐプレイ」を指がつつき、ボタンを光の帯が横切る。
- プレイヤーは、最初のボス（月曜日）を倒すとスーツ姿になる（濃紺の上着、茶色のかばん、白い襟、革靴。`player.suit`）。一時停止の画面には「（離席中）」と添える。
- ブロックを壊したときに中央へ出す効果名は、ランクアップ！、エナドリ！ ランク +2（小さく「元気の前借り」）、相棒 参上！（2 台目は「AI 相棒 参上！」と、小さく「お手伝いできることはありますか？」）、一斉削除！、有給休暇！、キャパ拡張！ 容量 +10、通知が止まらない！、帽子ゲット…。ボスを倒すと「〈ボス名〉撃破！」。
- 有給休暇の効果中は、敵の帯を水色にして残り秒数を道の上に出す。
- 敵の絵は、当たり判定の幅に合うよう種類ごとに倍率を掛けている（未読通知 1.3 倍、締切とリボ払い 1.2 倍。`src/render/view.ts` の `ENEMY_SCALE`）。
- ボスが出た瞬間は、画面中央の帯に名前を大きく 2 秒出し、少し遅れて下にボスのひとことを出す。ボスがいる間は、中央上に名前と HP バーを出す。
- WAVE の進行バーは、凪を青、ラッシュを赤、ボス戦のウェーブのラッシュを紫で塗る。
- ゲームオーバーでは、敵のスプライトが手前へ大きくなりながらなだれ込み、画面が赤黒くなる。
- リザルトの社会人力が 1 万未満（`LOW_POWER`）なら、数字の下に「私の社会人力、低すぎ…？」を添える。表示は `formatPower`（万・億・兆・京・垓。垓を超えたら「測定不能」）。
- 「結果をコピー」は、成功すると「コピーしました」、クリップボードが使えない環境では結果の 1 行（称号・ハッシュタグ・URL は除く）を画面に出す。「X にポスト」は、`window.open` で投稿画面を別のタブに開く（`noopener,noreferrer`。開いた先からこのページを操作できないように）。ボタンは、白いボタンの並びの中で目に留まるよう黒い板にし、実在のロゴは描かない。
- 指で遊ぶ縦長の画面の「指を置く場所」は、画面下端の足場（鉄の床）がそのまま続いているように塗り、なぞる場所を溝の形で示して、左右の三角形と「ここをなぞって動かす」を出す（CSS の `body.finger::before` と `body.finger.playing::after`。黒い余白のままだと浮いて見えた）。溝は遊んでいる間だけ出す（一時停止やリザルトでは、なぞっても何も起きないため）。タイトルでは指を置く場所そのものをあけず、PC と同じく真ん中に置く（`App.inGameLayout`。タイトルとそれ以外で置き方が変わるので、切り替わったら `resize` し直す）。足場はキャンバスに 2px 重ね、継ぎ目を板の縁として描く（画面の高さに端数がある端末で、1px のすき間が見えたため）。幅はキャンバスの幅に合わせる（`--game-width`。キャンバスを縮めた端末で、足場だけが左右にはみ出さないように）。
- キャンバスの外の余白（PC の左右、縦長のスマホのタイトルの上下）には、ゲームの画面をぼかした背景を敷き、キャンバスに影を落とす。背景は別のキャンバス（`#backdrop`。幅 48px の小さな絵）で、0.1 秒ごとにゲームのキャンバスを余白が残らない向きに引き伸ばして写し、半分の濃さで暗くする。画面いっぱいに広げてぼかすのは CSS（`filter: blur`）。時間帯の色や、危険なときの赤が余白にも映る。余白がないとき（スマホで遊んでいる最中）は `hidden` にして描かない。背景を見せるために `body` は塗らず、描かれるまでの色（濃紺のグラデーション）は `html` に持たせる。スマホを横向きにしたとき（高さ 500px 以下の横長）は、余白の左下に「縦向きにすると大きく遊べます」と出す。PC の横長の画面（マウスがあり、幅が高さの 4/3 以上）では、同じ場所に操作の説明を出す。どれも CSS だけで行う。
- 版の目印は「ビルドした日時（日本時間の月/日 時:分）+ コミットの短い ID」。ID は CI が渡す `GITHUB_SHA` の先頭 7 文字で、手元のビルドでは `local`、開発サーバーでは起動した時刻になる。タイトルの左下（右下は、つつく指の絵に隠れる）と、一時停止の説明の下に、文字 10 の半透明で出す。
- リンクを貼ったときの題名・説明・画像（OGP）を `index.html` に書いてある。画像は `public/ogp.jpg`（1200 × 630）で、ビルドすると `dist/` の直下に写る。左に題名・ひとこと（「敵を撃つか、強化を撃つか。撃てるのは、正面だけ。」）・「今すぐプレイ」のボタンの絵、右にゲームの画面を 2 枚（昼の混戦、夜のレーザー）。ゲームの画面を 2 倍の解像度で撮り、文字と一緒に 1 枚の HTML（文字は SVG で、ゲームと同じ縁取りとグラデーション）に並べて、1200 × 630 で撮り直したもの。タイムラインの小さな表示でも、題名と何をするゲームかが読めることを優先している。見た目を大きく変えたら作り直す。`og:image` は絶対 URL で書く必要がある。`og:url` と `canonical` には公開先の URL を直接書いているので、公開先が変わったら `README.md` と合わせて直す。

### 仕様書の表示との違い

- プレイ中のスコアは、K・M 表記ではなく 3 桁区切りの整数で出す。1 点単位で増えるのが見えたほうが気持ちよいため。HP、DPS、ダメージは仕様どおり K・M・B・T。
- タイトル画面では、右上の「✕」のために埋まり度ゲージの幅を 460 にし、下端の「今すぐプレイ」のために武器名と DPS をスコアの下へ移している。警告の文字も小さくしている。
- 開始 10 秒間の案内は、手前の敵と重ならないよう道の中ほど（y 468〜556）に出す。

### 音

- 音は初めはオン。最初のタップかキー入力で鳴り始める。指で触れたときは、離した瞬間に有効にする（触れた瞬間は、ブラウザがまだ利用者の操作と認めず、警告が出るため）。設定は `docchi-utsunen.sound` に `on` / `off` で保存する。
- 発射音は武器の段階ごとに、波形・高さ・長さ・ノイズの量を変えている（`src/audio/synth.ts` の `SHOTS`）。
- BGM は 1 小節 = 8 分音符 8 個の 4 小節。ノコギリ波のベース、サイン波のキック、ノイズのスネアとハイハット、三角波のメロディ（WAVE 2 から）でできている。テンポは WAVE 1 で 104、1 ウェーブごとに +4、上限 168。和音の進行は、ふだんが Am → F → C → G、ボス戦のウェーブが Am → Dm → E → Am。
- 効果音と BGM は別々の系統（`sfxBus`、`bgmBus`）にまとめ、圧縮器（DynamicsCompressor）を通してから出す。
- 音の減衰は「すばやく立ち上がり、3% まで減って、最後に短くゼロへ」。ゼロ近くまで一気に減らすと、一瞬の「チッ」という音にしかならず聞こえにくい（最初の実装がそうだった）。
- 会心の音は、三角波の高い音（ラからド♯へ上がる 0.06 秒）。発射音に埋もれず、連続しても耳に刺さらない高さと短さにした。秒間 10 回まで。
- 同じ音が続いても機械的に聞こえないよう、発射音と撃破音は高さを少し揺らす。ブロックを撃つ音は削れるほど高く、ランクアップの音はランクが上がるほど半音ずつ高くなる。
- 心拍は埋まり度 70% で 0.95 秒間隔、100% で 0.38 秒間隔。
- タイトル画面のボタンを押したときだけ、デモ中でも小さな操作音が鳴る（デモ自体の音は鳴らさない）。

### 操作

- タッチとマウスは画面全体で受ける。キャンバスの外の余白に触れても、その横位置を狙う。マウスはボタンを押さなくても、動かすだけで狙う。 指で遊ぶ縦長の画面では、`resize` がキャンバスを上に寄せて下をあける（`body.finger` と `--finger-area`。指で操作する端末かどうかは `(pointer: coarse)` で見る）。
- ボタンは触れた瞬間（pointerdown）に効くが、「結果をコピー」と「X にポスト」だけは、指やボタンを離したとき（pointerup）に実行する（`ON_RELEASE`）。クリップボードへの書き込みと別のタブを開く操作は、ブラウザが利用者の操作と認めたときしか通らず、指で触れた瞬間はまだ認められないため。
- キーは押している間だけ動く。押している間は立ちたい位置を道の端にし、離した瞬間に今の位置へ戻すことで止めている。ウィンドウがフォーカスを失ったら、押していない扱いにする。
- タイトル・一時停止・リザルトでは、Tab か矢印キーでボタンを選び、Enter かスペースで決定する。何も選んでいないときの決定は、いちばん上のボタン（今すぐプレイ、再開、もう一度）に効く。
- 実解像度は devicePixelRatio に合わせるが、2 倍を上限にしている。論理解像度（540 × 960）から実際の画素への拡大率は、横と縦で別々に持つ。大きさを整数に丸めるので、片方の拡大率だけで描くと、もう片方が 1 画素ぶん足りず、端の 1 行が塗られないまま残る（下端に赤い線が残る不具合になっていた）。

## 確認のしかた

- 単体テスト・バランス検証・型検査・ビルドのコマンドは `CLAUDE.md` の「コマンド」。
- 参照との一致を種ごとに見るときは `docker compose run --rm sim node src/sim/cli.ts --seeds` の出力を、`reference/golden.json` の `sim_reference.*.first10_seeds` と見比べる。
- 見た目は、Playwright 公式イメージ（digest 固定）の Chromium を CDP で操作してスクリーンショットを撮る。npm パッケージは入れず、Node 標準の `fetch` と `WebSocket` を使う。確認用スクリプトと撮った画像はリポジトリに入れない。
    - コンテナは compose のネットワーク（`docchi-utsunen_default`）につなぎ、開発サーバーのコンテナの IP アドレスで開く（Vite は知らないホスト名での接続を拒むため。IP は `docker inspect` で調べる）。
    - 和文は Windows のフォントフォルダを読み取り専用でマウントして `fc-cache -f` する。Chromium には `--no-sandbox`（権限を落としたコンテナではサンドボックスを作れない）と `--disable-dev-shm-usage` を付ける。
    - 後半の場面を作るには、`window.app` から `app.session.advance(1/60)` を繰り返し呼んで早送りし、`app.session.state` を書き換える。ボットに操作させるときは `app.session.aim` に立ちたい横位置を入れる。ボットに遊ばせるなら、ページ内で `import('/src/bots/skill.ts')` する。
    - スマホ向けの確認は、タッチのエミュレーション（390 × 800 など）で行う。キャンバスが画面より小さいと上下に余白ができるので、タップする座標は余白のぶんずらす。
    - 本番ビルドは `preview` を同じ方法で開く。CSP 違反はコンソールのログに出るので、ログが空であることを確かめる。
- Chromium 以外のエンジンでも確かめるときは、同じイメージに入っている Firefox と WebKit（Safari と同じ系統）を使う。この 2 つは CDP では動かせないので、確認用のコンテナの中だけに、イメージと同じ版の `playwright` を入れて動かす（リポジトリはマウントしない。ホストにも `package.json` にも入れない）。WebKit は、スクリーンショットを撮るたびに「スタイルシートを CSP が拒んだ」というエラーをコンソールに出すが、これは Playwright が撮影のために差し込むスタイルで、ゲームのものではない。コンソールが空かどうかは、撮影しない回で見る。
- 音は、耳で確かめられない代わりに数値で確かめる。ページの中で `OfflineAudioContext` を作って `new Synth(true, その context)` に渡し、効果音や `renderBgm` を呼んでから書き出して、最大音量と平均音量（RMS）を測る。見るのは、音割れ（最大 1 以上）がないこと、無音でないこと、効果音が BGM に埋もれていないこと。今の値は、BGM の最大 0.5〜0.6、発射音 0.1 前後、会心の音 0.09 前後、全部重ねても最大 0.7 弱。
- 混雑時の重さは、敵をたくさん置いて更新と描画を 120 回まわし、1 回あたりの時間を測る（測った値は `docs/decisions.md` の確認項目の表）。
- 堅さは、ページを開く前に `localStorage`・`AudioContext`・`navigator.clipboard` を使えなくして操作し、コンソールが空であることを見る。長時間の動作は、容量を外してボットに 20 分ぶん遊ばせ、見た目の状態（`View.enemies` など）の数が増え続けていないことを見る。
- ボットの遊び方の内訳（強化の帯にいた割合、弾が当たっていた割合、会心の割合など。仕様書 11.2 節）は、`step` を回しながら数える小さなスクリプトで測った。会心の割合は、状態の「当たっていた刻みの数」と「会心だった刻みの数」から出る。狙いのぶれの効き目は、`createSkillBot` に渡す `aimError` だけを変えて比べた。スクリプトはリポジトリに入れていない。
